# 网站巡检

在项目目录执行：

```powershell
npm.cmd run ops:check -- https://你的域名 work/site-check-20261107.json
```

目标必须是根源地址，不包含账号、路径或查询参数。只允许本机HTTP，其他地址必须HTTPS并正常验证证书；第三个可选参数是本地演练CA文件，不会关闭证书验证。报告路径的父目录需存在，每次使用新文件名，不覆盖历史报告。

每次同时检查/dashboard的SPA入口、/api/health的服务标识和/api/ready的数据库与Redis连接。默认每个请求8秒总时限，最多接收1MiB，不跟随跳转；状态码200但内容不符也失败。生产巡检不接受development-memory缓存。报告只含检查时间、源地址、固定路径、耗时、状态码和固定原因，不保存响应正文、账号或请求凭据。

全部通过退出0，故障或参数/报告写入错误退出1。可以由未来的服务器监控系统读取退出码；当前只提供单次巡检，未安装定时任务，也没有发送邮件、短信等外部告警。这个命令不会重启服务或修改业务数据。

## 故障处理

- /dashboard失败：检查前端容器、反向代理和证书。
- /api/health失败：检查API进程和代理路径。
- health正常但ready失败：检查数据库、迁移和Redis。报告不会猜测具体失败依赖，需进一步查看受限服务日志。
- connection-or-tls-error：检查连接与证书；不要通过关闭证书验证掩盖问题。
- timeout：检查服务响应与主机负载。

`npm run test:ops`覆盖正常服务、依赖未连接、跳转、HTML伪成功、超时及非法地址。`npm run verify:containers`额外在隔离HTTPS环境执行巡检、停止测试Redis确认报警状态，再恢复Redis确认恢复正常。该故障演练只操作脚本创建的测试资源。

检查SPA入口不代表浏览器交互全部正常；不检查登录后业务、磁盘空间、备份新鲜度、证书剩余天数或真实模型。正式上线仍需持续监控、通知接收人、容量与恢复演练安排。
