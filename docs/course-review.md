# 课程审核与发布管理

2026-11-06：已实现本地课程送审、独立管理员通过/退回、版本快照、审核历史及服务端发布门槛。仅新增审核表，不自动送审或发布现有课程。

## 使用流程

1. 管理员保存课程草稿并分配授课教师。编辑器可填写适用地区、教材出版社/版次/ISBN依据与学期；未核验内容留空，不自动推断湖北选用版本。
2. 已分配教师在“我的教学课程 → 审核 / 记录”查看已保存内容，提交审核；管理员也可以提交。
3. 管理员在“课程管理 → 审核 / 记录”检查正文、例题、视频及使用依据。通过时四项确认必填，并填写10至2000字意见；资料不完整可退回修改。
4. **提交人不能审核自己的提交。** 教师送审、管理员审核即可；若管理员自行送审，需要另一位管理员审核。不能为了通过测试自动赋予真实账号管理员权限。
5. 审核通过后，由管理员在课程列表单独点击“发布”。审核通过不直接开放学生访问。
6. 已发布课程先转草稿才能编辑。重新保存后的内容指纹与已通过快照不一致，必须重新送审；旧记录保留，不覆盖原意见。

教师现可修改本人草稿的说明、现有章节/课时标题与正文，见[教师改稿](teacher-course-revision.md)；结构、排序与视频由管理员维护。教师仍无发布权限。取消教师归属后，该教师立即失去审核历史和送审访问权限。

## 版本与边界

- SHA-256指纹包含课程名称、标识、年级、学科、简介、访问权限、地区、教材版本、学期、章节/课时顺序及ID、正文和视频编号。
- 发布仅接受最新记录为APPROVED且指纹与当前已保存内容一致的课程。页面显示“未提交、待审核、通过、退回、内容已变更”。内容相同的草稿/发布状态切换不改变内容指纹。
- 提交和审批携带当前课程updatedAt；陈旧请求返回409。事务内先校验/锁定当前账号，再锁定课程，与保存、分配归属及发布串行。重复提交或并发审批只能产生一次有效结果。
- 每次送审保存独立正文快照；结论只能从PENDING写一次。保存审核人、提交人ID及当时显示名、时间、意见与通过检查项；账号后续改名/删除不会改写记录中的身份快照。课程删除会级联删除其审核记录，正式数据保留策略仍待确定。
- 本轮审核对象是课程文字与视频引用，**不包括独立题库题目、考试卷或视频文件内容快照**。视频须在素材中另行观看核验；四项勾选是审核人确认，不是系统自动证明版权、教材适配或教学质量。
- 本地已有已发布课程不自动下架；今后的发布接口调用必须通过审核门槛。原始3份课程草稿没有送审、审批或发布。

## API

统一响应`{code,message,data}`，成功code=0。

| 方法与路径                                      | 权限与输入                                          | 结果                                                      |
| ----------------------------------------------- | --------------------------------------------------- | --------------------------------------------------------- |
| GET /api/courses/:id/reviews?page=1&pageSize=10 | ADMIN或当前归属TEACHER                              | page/pageSize/total/list及current当前状态、快照、最新记录 |
| POST /api/courses/:id/reviews                   | ADMIN或归属TEACHER；{updatedAt}                     | 保存PENDING版本快照                                       |
| POST /api/courses/:id/reviews/decision          | ADMIN；{reviewId,updatedAt,status,feedback,checks?} | 通过或退回                                                |
| PATCH /api/admin/courses/:id/status             | ADMIN；{status}                                     | PUBLISHED增加审核门槛；DRAFT/ARCHIVED沿用原含义           |

审批status为APPROVED或RETURNED。APPROVED必须带`checks:{accuracy:true,alignment:true,rights:true,readability:true}`，RETURNED不带checks；feedback必填10至2000字。输入由DTO的Zod schema及validate中间件校验，业务授权和版本规则位于service，数据库访问位于repository。
