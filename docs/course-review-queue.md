# 管理员课程审核队列

管理员在学习中心和课程管理页查看审核队列，按送审时间从早到晚排列，每页5条。队列只列出当前仍为DRAFT、且最新审核记录为PENDING的课程；每门课程最多出现一次。更新的送审、退回或通过记录会覆盖旧待审记录的队列资格，但不会删除历史。

队列总量包括以下状态，不能理解成全部可直接审核：

- 可审核：送审指纹与当前内容一致，且当前管理员不是提交人。
- 内容已变更：指纹不同，需重新送审；进入记录可核对变更。
- 本人提交：须由其他管理员处理；如果版本也已变更，两项提示同时保留。

点击入口打开原课程审核面板。队列摘要不包含正文、历史快照、内容指纹或审核意见。进入面板后仍须逐项核对、填写意见并明确提交；审核决定与课程发布保持独立。关闭面板自动刷新队列，也可手动刷新。打开的审核面板独立于列表加载，刷新列表不会丢弃面板中的填写状态。

## 数据与权限

`GET /api/admin/course-review-queue?page=1&pageSize=5` 仅有效管理员可读，pageSize最大20，拒绝未知参数。响应 `CourseReviewQueue` 并设置 `Cache-Control: no-store`。

读取在RepeatableRead事务内完成，重新核验管理员角色；数据库使用NOT EXISTS及提交时间/id的顺序判断每门课程的最新记录，再计数和分页。只为本页最多20门课程读取当前正文计算指纹，复用原审核逻辑，不加载全部审核历史。页码超出结果范围返回空列表及真实总量。

队列展示是读取时的版本；最终审核接口重新检查当前内容、版本、记录及提交人，防止队列加载后内容变化或其他管理员先行处理。此接口不送审、不做审核决定，也不发布课程。

## 验证

`npm.cmd run test:review-queue` 纳入verify，随机合成账号及课程按精确ID清理，覆盖管理员权限、严格分页、最早送审排序、最新记录去重、已发布/已归档排除、内容失效、自审禁止、决定后出队、角色变化及摘要不包含正文。通过/退回仅用于合成协议验收，不代表对真实课程作出教研结论。原审核测试 `test:review` 同时回归。

浏览器使用独立localhost源与合成管理员，核对可审核、版本变更、自审三类入口及390px布局。原127.0.0.1会话、原3门课程与其发布状态保留。
