# 教师教学待办

教师在学习中心 `/dashboard` 查看“教学待办”。每分钟及窗口重新获得焦点时刷新，也可手动刷新；时间使用北京时间。

## 待批改

- 显示当前教师名下、当前仍由本人管理的有效班级中、已发布作业的未批改提交。作业截止后仍需批改，故不按截止时间排除。
- 同时显示待批改份数和涉及作业数量。数据库聚合后按每项作业最早待批改提交的时间排序，最多显示5项作业。不会把前5项的份数误当成全部总量。
- 不排除退班学生的既有提交，沿用原作业批改权限和历史保留规则；作业归档、班级归档、班级转交或教师角色失效后，相应待办不再显示。
- 点击“查看与批改”打开对应作业详情。提交表格现在优先排列未批改记录，再按提交时间排列，避免未批改记录被大量已批记录挤到后续页。每页仍为10条，已批成绩与历史记录保留。

## 课程草稿

只列出 `ownerTeacherId` 为当前教师且状态为 `DRAFT` 的课程，显示完整数量和最近修改的5门。它是草稿入口，不代表每门都需要修改或送审；实际审核进度仍由课程审核面板给出。

`/teacher/courses?courseId=...` 可直接打开归属课程的详情，详情内有现有改稿和审核入口；关闭详情清除参数。即使课程不在列表当前分页，也可读取有权访问的详情。课程转交后原教师访问返回404。改稿、送审、审核和发布仍须各自明确操作。

## 接口及验证

`GET /api/analytics/teacher/tasks` 仅当前有效教师可读，禁止指定其他教师。RepeatableRead事务内检查身份并聚合，响应 `TeacherTasks` 并设置 `Cache-Control: no-store`。只返回课程/作业名称、班级名、时间和数量，不返回私人作答、学生名单、答案、分数和反馈。接口不批改、不送审、不发布。

`npm.cmd run test:teacher-tasks` 已纳入 `verify`。使用随机合成账号和独立班级，按精确ID清理，覆盖权限隔离、完整计数与限量排序、已归档排除、已批移除、未批记录优先、课程发布/转交和教师角色变化。作业变更另跑 `test:homework`。

浏览器验收使用独立 localhost 源及合成教师，不替换127.0.0.1上用户原有会话；不修改原3门课程或其发布状态。
